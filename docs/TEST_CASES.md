## 一、API 模型调用

### TC-API-01: 基本调用——qwen-max (OpenAI 兼容渠道)

- **描述**: 用令牌通过网关转发调用千问 qwen-max 模型，走 OpenAI 兼容接口 `https://dashscope.aliyuncs.com/compatible-mode`
- **前置条件**: qwen-max 渠道 status=1, base_url=`https://dashscope.aliyuncs.com/compatible-mode`, 令牌包含 qwen-max 模型权限
- **步骤**:
  1. 执行 `POST /v1/chat/completions`
  2. Header: `Authorization: Bearer <token_key>`, `Content-Type: application/json`
  3. Body: `{"model":"qwen-max","messages":[{"role":"user","content":"hi"}],"max_tokens":10}`
- **预期结果**: HTTP 200, `choices[0].message.content` 返回正常英文或中文回复
- **判定标准**: 返回 `"object":"chat.completion"`，`finish_reason` 为 `stop` 或 `length`
- **状态**: ✅ 通过

### TC-API-02: qwen-plus 调用

- **描述**: 同上，model=qwen-plus
- **前置条件**: 令牌包含 qwen-plus 模型权限
- **预期结果**: HTTP 200, 正常回复
- **状态**: ✅ 通过

### TC-API-03: qwen-turbo 调用

- **描述**: 同上，model=qwen-turbo
- **预期结果**: HTTP 200, 正常回复
- **状态**: ✅ 通过

### TC-API-04: kimi-k3 调用 (腾讯云)

- **描述**: 通过网关调用腾讯云托管的 kimi-k3 模型
- **前置条件**: kimi-k3 渠道 status=1, base_url=`https://tokenhub.tencentmaas.com`, 令牌包含 kimi-k3
- **预期结果**: HTTP 200, 正常回复
- **状态**: ✅ 通过

### TC-API-05: deepseek-chat 调用

- **描述**: 通过网关调用 DeepSeek API
- **前置条件**: deepseek-v4 渠道 status=1, base_url=`https://api.deepseek.com`, 令牌包含 deepseek-chat
- **预期结果**: HTTP 200, `model` 字段为 `deepseek-v4-flash` 或 `deepseek-chat`
- **状态**: ✅ 通过

### TC-API-06: 令牌无权使用某模型

- **描述**: 请求令牌 models 列表中不包含的模型，网关应拒绝
- **步骤**: 将令牌 models 设为 `"qwen-max"`, 请求 model=`deepseek-chat`
- **预期结果**: HTTP 403, `error.type="one_api_error"`, message 包含 `"无权使用模型"`
- **判定标准**: 不会转发到上游渠道，直接在网关层拦截
- **状态**: ⬜ 待测

### TC-API-07: 令牌已过期

- **描述**: 使用 `expired_time` 小于当前时间戳的令牌
- **步骤**:
  1. 设置令牌 expired_time 为 `1780000000`（过去的时间）
  2. 用该令牌请求任意模型
- **预期结果**: HTTP 403, message 包含 `"已过期"`
- **状态**: ⬜ 待测

### TC-API-08: 无效令牌

- **描述**: 使用不存在或被删除的令牌 Key
- **步骤**: 伪造一个 `sk-fake123...` 的 Key，请求任意模型
- **预期结果**: HTTP 403, message 包含 `"无效的令牌"`
- **状态**: ⬜ 待测

### TC-API-09: 令牌额度耗尽

- **描述**: 令牌 unlimited_quota=false 且 remain_quota=0 时，请求被拒绝
- **步骤**:
  1. 设置令牌 unlimited_quota=false, remain_quota=0
  2. 用该令牌请求模型
- **预期结果**: HTTP 403, message 包含 `"额度不足"` 或 `"quota is not enough"`
- **状态**: ⬜ 待测

### TC-API-10: 流式输出 (SSE)

- **描述**: 请求 `stream:true` 时返回 Server-Sent Events 流
- **步骤**:
  1. `POST /v1/chat/completions`, Body 含 `"stream":true`
  2. 逐行读取响应体
- **预期结果**: 响应头 `Content-Type: text/event-stream`，每行以 `data:` 开头，最后一行 `data: [DONE]`
- **状态**: ⬜ 待测

### TC-API-11: 请求模型不存在于任何渠道

- **描述**: 请求一个所有渠道都不支持的模型名
- **步骤**: model=`nonexistent-model-xyz`
- **预期结果**: HTTP 4xx, 提示模型不可用
- **状态**: ⬜ 待测

### TC-API-12: 渠道全部不可用时

- **描述**: 所有渠道 status=0（禁用）时请求
- **步骤**: 禁用所有渠道后请求 qwen-max
- **预期结果**: HTTP 5xx, 提示无可用渠道
- **状态**: ⬜ 待测

### TC-API-13: health_check 探测

- **描述**: 系统每 60 秒对启用的渠道发送 `POST /v1/chat/completions` 探测，model 取渠道 models 字段最后一个
- **步骤**: 查看服务日志，确认健康检查周期运行
- **预期结果**: 启用渠道 → 日志无 "Health check failed"；禁用渠道 → 不探测
- **判定标准**: `[runHealthCheck] Health check failed for channel #X` 仅出现在真正挂掉的渠道
- **状态**: ⬜ 待测

## 二、登录与鉴权

  2. 输入用户名 `root`、密码 `123456`

- **描述**: 管理员通过浏览器表单添加一个新的 OpenAI 兼容渠道
