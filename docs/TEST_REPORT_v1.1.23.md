## 二、本轮修复的 3 个 Bug（v1.1.21 ~ v1.1.23）

### Bug 1: 用户无法自助修改密码（TC-AUTH-05 / TC-AUTH-06）

- **关联用例**: TC-AUTH-05（修改密码）、TC-AUTH-06（确认密码不一致）
- **现象**: 「设置 → 个人设置」没有自助修改密码的入口；One API 原生仅支持管理员在用户管理页改他人密码，无面向当前用户的改密接口。
- **根因**: 缺少 `POST /api/user/password` 后端接口 + 前端 PersonalSetting 三字段表单。
- **修复** (v1.1.22, commit `5287897`):
  - 后端 `controller/user.go` 新增 `ChangePassword`，校验旧密码(`ValidatePasswordAndHash`)、新密码非空且 ≥8 位，成功后 `Password2Hash` 落库。
  - 路由 `router/api.go` 注册 `selfRoute.POST("/password", controller.ChangePassword)`。
  - 前端 `PersonalSetting.js` 新增三字段表单（旧密码/新密码/确认密码），前端校验两次输入一致。
- **验证**: curl 调用改密接口通过；浏览器表单提交后旧密码失效、新密码可登录；确认不一致被前端拦截。**✅ 通过**

### Bug 2: 管理员生成系统访问令牌失败（TC-AUTH-08）

- **关联用例**: TC-AUTH-08（生成系统访问令牌）
- **现象**: 管理员点击「生成系统访问令牌」返回错误 / 无法生成 token。
- **根因**: `controller/user.go` 的 `GenerateAccessToken` 中有 `if role >= 10 { id = 0 }` 逻辑，把管理员 id 强制覆盖为 0（不存在的用户），导致 `GetUserById(0)` 查不到记录。
- **修复** (v1.1.21, commit `8e693f0`): 删除 `id = 0` 覆盖分支，管理员改用当前登录用户 id。
- **验证**: curl 调用接口返回 UUID access token。**✅ 通过**

### Bug 3: 令牌月度额度保存静默丢失（TC-TK-07）

- **关联用例**: TC-TK-07（编辑令牌——月度额度）
- **现象**: 编辑令牌填「月度额度」并提交，前端提示成功，但 DB/API 的 `monthly_quota` 仍为 0。
- **根因** (两处叠加):
  1. 前端 `EditToken.js` 用 `parseInt` 换算额度，小数被整数截断（v1.1.21 修复为 `parseFloat` + `Math.round`，commit `8e693f0`）。
  2. 后端 `UpdateToken` 未把 `token.MonthlyQuota` 赋值给 `cleanToken`；且 `model/token.go` 的 `Update()` 用 `Select()` 白名单指定更新字段，白名单缺 `monthly_quota`，赋值了也不会落库（静默丢失，v1.1.23 修复，commit `be0da06`）。
- **修复**:
  - v1.1.21: `EditToken.js`/`AddUser.js`/`EditUser.js` 的配额换算 `parseInt`→`Math.round(parseFloat(...))`。
  - v1.1.23: `controller/token.go` 增 `cleanToken.MonthlyQuota = token.MonthlyQuota`；`model/token.go` `Update()` Select 白名单补 `monthly_quota`。
- **验证**: API 提交 monthly_quota=500（内部单位 500000000），保存成功后查询确认 `monthly_quota=500000000`。**✅ 通过**
